STT Word Error Rate (WER)

WER by Provider

Word Error Rate measures STT accuracy by comparing transcripts against reference text. Industry target: <10% (0.10). Lower is better. WER = (Substitutions + Deletions + Insertions) / Reference Words.

Interruption Rate

Percentage of turns where user interrupted the agent (barge-in). Target: <15%. High rates suggest the agent speaks too long or is too slow.

Latency Metrics

LLM Time to First Token (seconds)

Time from sending the prompt until the first token arrives. Industry target: <0.5s. Lower is better — directly impacts perceived responsiveness.

How to read: Compare Avg and P95 bars. A large gap between P50 and P95 indicates inconsistent latency. Look for the shorter bars — that provider responds faster.

LLM Tokens per Second

Speed of token generation after the first token. Industry target: >30 tok/s. Higher is better — affects how quickly the full response streams to TTS.

How to read: Taller bars = faster generation. A consistent Min close to Avg means stable throughput. Large Avg-to-Min spread indicates throttling or cold starts.

End-of-Utterance Delay (seconds)

Delay from when the user stops speaking to when the system detects end-of-utterance. Industry target: <0.5s. Lower is better — long delays feel laggy to callers.

How to read: This reflects VAD + STT pipeline latency. Compare P95 to see worst-case pauses. Values >1s may indicate the turn detector is too conservative.

Time to First Audio (seconds)

Total time from end-of-utterance to when the user first hears the agent's response. Industry target: <1.0s. This is the most important metric for perceived latency.

How to read: TTFA = EOU delay + LLM TTFT + TTS TTFB. This is the "end-to-end" user experience metric. Compare Avg bars to see overall winner.

TTS Time to First Byte (seconds)

Time for the TTS engine to return the first audio chunk after receiving text. Industry target: <0.3s. Lower is better — contributes to overall TTFA.

How to read: Since both providers use OpenAI Nova TTS in this benchmark, values should be similar. Differences indicate network or queuing variations.

STT Transcription Delay (seconds)

Time from end-of-utterance to when the final transcript is available. Industry target: <0.4s. Lower is better — Parakeet (NVIDIA) vs Nova (Deepgram) comparison.

How to read: Compares raw STT performance. Deepgram typically has lower latency due to edge-optimized models. NVIDIA Parakeet may have higher accuracy trade-offs.

Turn Round-Trip Time (seconds)

Full time from when the user stops speaking to when the agent starts speaking. Industry target: <1.5s. Lower is better — measures the complete pipeline delay per conversation turn.

How to read: Turn RTT captures the entire processing chain (VAD + STT + LLM + TTS). This is the most holistic latency metric. Compare P95 to understand worst-case user experience.

Session Duration (seconds)

Total wall-clock time for each agent session. Benchmark: varies by scenario. Consistent durations indicate stable performance; large variance may signal timeouts or errors.

How to read: Compare session lengths across providers. Shorter sessions with the same scenario may indicate faster responses. Outliers suggest connectivity or processing issues.

Metric Trend Across Runs

Each point represents one run's average value. Track consistency and regressions over time.

How to read: A flat line indicates consistent performance. Upward trends in latency metrics signal degradation. Compare the two provider lines to see which is more stable.

Understanding the Metrics

WER (Word Error Rate)

Measures transcription accuracy. Lower is better. WER = (Substitutions + Deletions + Insertions) / Reference Words. 0% = perfect, >20% = poor.

RTF (Real-Time Factor)

Processing time divided by audio duration. RTF < 1.0 means faster than real-time. Lower is better. RTF 0.1 = 10x faster than real-time.

Cold Start Latency

Time for the very first inference. Includes model loading, connection setup, and warmup. Typically 2-10x slower than warm latency.

Warm Latency

Average time for subsequent inferences after warmup. Represents steady-state performance. This is what users experience in production.
